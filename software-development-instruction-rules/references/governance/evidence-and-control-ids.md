# 控制编号与证据记录

仅在需要持续审查、跨版本比较、例外管理、控制矩阵或机器可读结果时读取。普通一次性评审可用简化表格，但不得省略版本、实际结果和证据定位。

## 稳定控制编号

- `GEN`：通用不变量；`GOV`：治理计划；`TRC`：追踪一致性；`QSC`：配置、质量与安全。
- `INI`、`REQ`、`DES`、`IMP`、`VER`、`REL`、`OPS`、`RET`：八个生命周期阶段。
- `SEC`：安全设计与供应链；`PRV`：隐私数据；`SUP`：采购供应商；`VUL`：漏洞与支持；`AI`：AI 专项。
- `-G` 后缀表示阶段退出门禁，例如 `REL-G01`；其余编号表示持续或阶段内控制。

控制编号是稳定引用，不替代条款正文。修改条款含义时保留历史说明或分配新编号；不要把同一编号复用于不同义务。诊断问题、知识说明和证据示例不需要编号。

## 单项证据记录

每项适用控制至少记录：

| 字段 | 含义 |
| --- | --- |
| `control_id` | 控制编号 |
| `scope` | 被评估的交付增量、系统或组件 |
| `applicability` | `APPLICABLE` 或 `NOT_APPLICABLE`；后者附理由 |
| `status` | `PASS`、`CONDITIONAL`、`BLOCKED` 或 `NOT_ASSESSED` |
| `evidence` | 可定位链接、路径、记录编号或实际观察；不得只写“已完成” |
| `artifact_version` | 证据对应的需求、源码、构建、配置或发布版本 |
| `observed_result` | 执行条件、实际结果和结论 |
| `owner` | 负责补齐或维持控制的人；未知时明确标记 |
| `checked_at` | 检查时间或证据产生时间 |
| `valid_until` | 有时效的证据到期点；不适用时省略 |
| `exception_id` | 关联例外或风险接受记录；无则省略 |

自动化工具可输出 JSON、CSV 或表格，只要字段语义等价。没有机器化需求时，不强制创建额外文件。

## 状态使用

- 未取得材料、尚未执行检查或无法访问证据：`NOT_ASSESSED`。
- 已检查且项目应当存在的必需证据缺失，或实际结果违反强制条件：`BLOCKED`。
- 强制条件均满足，仅有不阻断遗留事项：`CONDITIONAL`。
- 适用的强制条件均有版本匹配的证据且无未处置重大风险：`PASS`。

一条控制只覆盖部分范围时，拆分记录或明确未覆盖部分，不得以局部通过代表整体通过。

## 例外与剩余风险

例外记录至少包含唯一编号、涉及控制、适用范围、理由、影响、补偿措施、负责人、有权批准者、批准状态、开始与到期时间、复查触发条件及关闭证据。例外到期、范围变化、补偿措施失效或风险显著变化时，原结论自动需要重评；未署名或无期限的“暂时接受”无效。

## 一致性与漂移检查

评审前建立权威材料映射，至少确定需求、接口、数据规则、源码修订、构建、配置、测试和发布版本。发现链接失效、版本错配、重复编号、相互矛盾或下游材料未同步时，记录差异、权威来源、处理决定和负责人。不得通过覆盖旧记录来隐藏历史决定。
