# 计划与估算方法

仅在用户需要项目计划、工期、资源、依赖或进度预测时读取。估算帮助决策，不是对未知工作的确定承诺；小任务可用历史吞吐量和简单依赖清单。

## 从目标到可估算工作

1. 从可验收的交付增量出发，把产品工作、验证、集成、数据迁移、部署、培训和外部审批纳入范围。先检查遗漏，再估算。
2. 工作分解结构（WBS）按成果或工作包拆解；每个末端工作包要有可判断完成的结果、负责人和依赖。不要把岗位或日历周误当成果。
3. 活动网络标明前置、并行、外部依赖和等待时间。区分工作量（人时/人日）与历时（日历时间）；增加人员未必缩短不可并行的等待。
4. 识别人员容量、技能、共享资源、假期和交接成本；同一个人被分配到多个并行活动时，须调整计划。

## 选择估算方法

- 有可比历史：使用同类工作项吞吐量、周期时间或实际工时，说明差异和样本规模。
- 初期范围粗略：用类比或自上而下区间估算，单独列出未知项，避免把粗估报成承诺日期。
- 范围可拆分：按工作包自下而上估算，补上集成、协调、测试和返工；不要简单把所有并行活动历时相加。
- 不确定性显著且能给出合理输入：记录乐观值 O、最可能值 M、悲观值 P，可用 PERT 期望历时 `(O + 4M + P) / 6` 作单项参考。三点值是主观假设，不代表统计置信区间。
- 多条路径、共享资源或风险相关性会影响总工期时，可用基于明确分布与依赖假设的模拟。报告输入、敏感性和概率口径；输入不足时只给情景区间。

## 进度与风险

- 关键路径由依赖网络上的最长路径决定，关键活动延误会影响完工日期；资源约束可能改变实际关键路径。可见的浮时不等于可以无成本消耗。
- 为外部接口、采购、决策和审查设置责任人、需要日期、延误触发信号和替代方案。
- 风险储备应说明对应的不确定性；不要把储备藏在每个活动中又重复计入。固定日期下，明确缩减范围、增加资源、分阶段交付或接受风险的决策选项。
- 执行中用已完成且验收的成果、实际吞吐量和剩余工作滚动预测。挣值管理只在范围、成本基线和实际成本可靠时使用；不要用“已花时间”代替“已完成价值”。

## 计划门禁问题

- 范围及“完成”的定义是否清楚？集成、验证、迁移和交接是否被计入？
- 哪些活动控制日期，哪些依赖不受团队控制？日期变化时谁有权调整范围或资源？
- 对估算输入、区间、不确定性及基线变更是否留有可复核记录？

交付可是一页计划、工单看板或正式项目计划；形式取决于风险和已有制度。若无法确认关键依赖与能力，就不能把目标日期判定为有证据支持的可行承诺。
