# 采购与供应商控制

在采购或续约 SaaS、商业组件、外包开发、托管服务、数据服务或关键开源组件时读取。供应商材料是证据输入，不因品牌、合同或认证声明自动视为控制已经满足。

- [SUP-01] 明确拟采购能力、使用范围、数据与集成边界、关键质量目标、法规合同约束、预算和退出条件，并与自建、复用或维持现状等适用方案比较。
- [SUP-02] 按风险评估供应商的安全、隐私、可用性、灾难恢复、开发与漏洞管理、分包方、数据位置、支持能力和财务或运营连续性。
- [SUP-03] 合同或等效约定须覆盖适用的服务目标、数据所有权与使用限制、事件和漏洞通知、审计或证据获取、变更通知、补丁支持、退出协助及数据返还或删除。
- [SUP-04] 对集成接口、身份权限、数据映射、容量、限流、错误处理、版本兼容和供应商故障降级进行设计与验证；供应商承诺不能替代本方端到端测试。
- [SUP-05] 建立供应商、商业组件和关键开源组件清单，记录版本、用途、负责人、支持终止日期、替代方案及影响的发布版本。
- [SUP-06] 持续监控重大服务变化、漏洞、所有权变化、许可变化、支持终止和服务水平；达到触发条件时重新评估、升级或启动退出计划。
- [SUP-07] 退出计划须说明数据导出格式与核对、依赖方迁移、凭据撤销、接口停用、历史访问、合同费用、数据删除证明和不可替代风险。

关键供应商无法提供必需证据时，根据影响判为风险、补充独立验证或阻断，而不是默认信任。尚未取得材料为 `NOT_ASSESSED`；已确认合同或能力不满足强制要求且无有效补偿措施为 `BLOCKED`。
