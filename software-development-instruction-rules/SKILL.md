# 软件开发阶段门禁规则

将软件生命周期约束作为可执行的阶段门禁。除非用户明确修改规则，否则“必须”和“不得”均为阻断性要求。

## 语言

- 按用户当前请求的语言回答：中文请求用中文，英文请求用英文。用户指定语言或要求双语时，遵照其要求。请求中英文混用且未指定语言时，以实质需求使用的语言为准。
- 需求编号、文件名、命令、代码、接口字段和原文引述保持不变。说明文字、阶段名称、证据说明及待办事项使用回答语言。翻译不得降低门禁要求的强度。
- 中文报告使用“通过（PASS）”“有条件通过（CONDITIONAL）”“阻断（BLOCKED）”“未评估（NOT_ASSESSED）”；英文报告使用相应英文代码。中文报告保留英文状态代码，便于检索和对照。
- 需要双语交付时，对应的中英文内容应并列呈现，两种语言中的门禁结论、证据和待办事项必须一致。

## 按需加载

先确定用户是在制定规则、评审就绪情况，还是处理某个交付物；再按阶段和风险选择参考文件。只读取当前任务相关的文件；跨阶段问题读取涉及的几个阶段，全流程审查再依次读取全部阶段。普通概念解释无需套用门禁报告；未检查项目证据时，不要仅凭本索引判断门禁通过或阻断。

- 制定通用规范、执行门禁判定、处理跨阶段追踪或输出审查结论时，读取 [全流程控制与判定](references/controls.md)。
- 立项、可行性、目标与交付计划：读取 [阶段一：立项与可行性分析](references/01-initiation.md)。
- 需求获取、分析、确认、变更与追踪：读取 [阶段二：需求分析](references/02-requirements.md)。
- 业务建模、架构、接口、数据与详细设计：读取 [阶段三：系统与详细设计](references/03-design.md)。
- 编码、代码审查、依赖与迁移实现：读取 [阶段四：编码实现](references/04-implementation.md)。
- 测试、缺陷、回归与业务验收：读取 [阶段五：验证与确认](references/05-verification.md)。
- 部署、数据切换、发布与恢复：读取 [阶段六：部署与发布](references/06-release.md)。
- 监控、故障、维护与持续改进：读取 [阶段七：运行与维护](references/07-operations.md)。
- 下线、数据处置与资源清理：读取 [阶段八：系统退役](references/08-retirement.md)。
- 需要制定工作分解、工期估算、依赖或进度预测时，再读取 [计划与估算方法](references/planning-estimation.md)。
- 需要选择、检查或维护 UML、业务流程、数据和架构模型时，再读取 [建模方法与一致性检查](references/modeling-methods.md)。

参考文件中的“必做事项、所需证据、退出门禁”共同构成该阶段的约束。规则制定可以从中选取适用条款；就绪评审需要检查证据并读取 [全流程控制与判定](references/controls.md)。若任务跨越相邻阶段，同时读取相关文件，并说明阶段间的输入、输出与未决风险。不得因为引用了本技能，就自动创建文档、调用外部服务或要求额外审批。
