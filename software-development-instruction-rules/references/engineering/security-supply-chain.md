# 安全设计与软件供应链

在变更涉及身份权限、敏感资产、外部输入、信任边界、源码托管、CI/CD、第三方依赖、公共制品或分发渠道时读取。按风险选择控制；内部低风险脚本不因本文件自动承担公共软件制品的全部要求。

## 威胁与安全需求

- [SEC-01] 识别关键资产、主体、攻击面、信任边界、潜在攻击者及正常与滥用场景；高影响威胁须关联安全需求、设计控制和验证方法。
- [SEC-02] 新增外部接口、权限模型、跨租户访问、敏感数据、密码学或重大架构变化时，必须更新威胁分析；过期威胁模型不得作为当前设计通过证据。
- [SEC-03] 安全默认值、最小权限、失败安全、审计和恢复要求须进入接口、配置和运行设计，不能依赖用户自行加固来弥补已知危险默认值。

## 开发与源码环境

- [SEC-04] 对源码托管、制品库、CI/CD 和生产发布权限实施可识别身份、最小权限、强认证及定期复核；高权限共享账号或无法追责的发布身份构成阻断。
- [SEC-05] 受保护分支或等效集成路径须限制直接写入，并对高风险变更实施适当的独立审查和必需检查；紧急绕过须形成有期限的例外与事后复核。
- [SEC-06] 开发、测试和构建环境中的机密须通过受控渠道注入并限制暴露；日志、缓存、制品、测试快照和诊断包不得意外携带机密或敏感数据。

## 依赖与组件

- [SEC-07] 新增或升级依赖前，验证名称、来源、维护状态、许可证、已知漏洞、发布完整性和替代方案；不得安装模型臆造、来源不明或与需求无关的包。
- [SEC-08] 对适用制品维护足以识别直接及关键传递组件的清单，例如 SBOM 或等效记录，并将组件版本关联到构建和发布版本。
- [SEC-09] 持续监控在役版本所含组件的安全变化；发现问题时评估可利用性、影响范围、缓解措施和修复版本，而不是只记录扫描器告警数量。

## 构建、来源证明与分发

- [SEC-10] 发布构建须使用受控且一致的构建流程，产物能够关联到预期源码、依赖、构建参数和构建平台；不得用未经验证的本地临时产物替换候选制品。
- [SEC-11] 高风险或公开分发制品须按适用策略采用隔离构建、加密摘要、签名或来源证明，并保护签名密钥及证明生成边界不受普通构建步骤篡改。
- [SEC-12] 发布或部署前须验证制品身份、完整性、来源证明及预期构建参数；证明存在但从未验证，不能作为供应链风险已受控的证据。
- [SEC-13] 制品、签名、来源证明、SBOM 和发布记录须按可追溯方式共同分发或可定位，并防止同一版本的证明被静默覆盖。

## 安全验证与响应准备

- [SEC-14] 根据威胁和技术栈选择代码、配置、依赖、动态、渗透或人工安全审查；工具结果必须对应实际修订并完成误报、影响和处置分析。
- [SEC-15] 发布前应确认安全事件检测、取证所需记录、机密轮换、依赖隔离、制品撤回及安全修复发布路径可执行。

退出判断：存在未处置的高影响威胁、无法追溯的发布制品、泄露机密、未经授权的源码或发布路径，或供应链证明与制品不匹配时，不得判定相关实现或发布门禁通过。
