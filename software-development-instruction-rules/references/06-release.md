## 阶段六：部署与发布

进入条件：候选版本、对应验证结论、发布范围和运行责任已明确；准备工作可提前进行，生产切换须按退出门禁评估。

必做事项：

- 将发布版本与可识别的源码修订、构建产物、配置集、依赖集和迁移版本绑定。
- 将机密与环境配置同源码和构建产物分开管理。
- 验证备份、迁移、容量、权限、监控、告警、运维责任及回滚或向前恢复方案。
- 记录发布负责人、时间安排、操作步骤、验证步骤、停止条件和回滚触发条件。
- 部署后对关键用户流程和系统健康状况进行冒烟检查。
- 对高风险数据迁移、切换或回滚进行与生产条件相称的预演；记录恢复所需时间和数据一致性验证方法。
- 确认运行人员获得操作步骤、告警解释、故障升级路径及已知限制。

### 发布知识与执行控制

- **发布单元**：明确候选版本包含的功能、缺陷修复、配置、迁移、依赖和特性开关；核对测试证据对应相同产物。不要在发布时临时从未验证修订重新构建。
- **环境差异**：核查环境变量、外部服务、容量、权限、网络与证书。正式环境的专有配置由受控渠道提供，机密不出现在发布说明或脚本日志中。
- **数据迁移**：定义迁移前备份或恢复点、耗时、锁影响、映射与校验、失败处理、重复执行行为。若回滚代码不能回滚数据，应写明前向修复、兼容窗口和最终决策条件。
- **切换策略**：根据影响面选择一次切换、分批、金丝雀、蓝绿或特性开关；这些策略不是通用必选项。为每一步确定观察窗口、成功指标、停止阈值、决策人和回退/前向恢复动作。
- **发布预演**：高风险步骤在尽可能接近生产的环境验证，包括权限、脚本耗时、真实量级数据、恢复与沟通。预演记录发现的问题及计划修订。
- **业务连续性**：确定维护窗口、用户通知、依赖方协调、服务降级与客服支持安排；高影响变更应说明谁在发布期间负责观察并作决定。
- **部署后证明**：核对版本、关键业务流程、错误率、延迟、队列积压、数据一致性和安全告警；有持续观察期时写明结束条件。冒烟通过只证明抽样路径可用。
- **交接**：给运行人员提供操作说明、仪表盘或查询方式、告警含义、值班和升级联系人、已知限制，以及回滚或前向恢复所需条件。

### 发布门禁检查

1. 候选产物、配置、迁移与通过验证的版本是否完全对应？
2. 数据和服务中断风险是否已有可执行的备份、恢复、停止与沟通方案？
3. 发布步骤由谁执行、谁监测、谁决定继续或停止，是否都已明确？
4. 部署后关键业务和技术指标如何验证；失败时多快能发现并采取什么行动？
5. 运维交接和必要的真实组织批准是否完成并可查？

所需证据：

- 项目制度要求的批准或发布授权记录
- 可复现的产物和配置标识
- 已验证的迁移及回滚或恢复方案
- 部署后验证和监控状态
- 切换、停止和恢复条件的验证记录
- 发布期间的决策和操作日志、部署后业务与技术检查结果

退出门禁：

- 未通过适用验收的构建，或对其影响缺少足够可观测性和可执行恢复路径的变更，不得宣布发布门禁通过。
- 达到预设安全阈值或验证失败时，必须停止发布或回滚。
- 若数据变更不可逆，不得承诺不存在的回滚能力；须在发布前确认前向恢复及风险接受。
